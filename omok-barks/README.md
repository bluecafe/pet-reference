# omok-barks

대국 중 캐릭터가 무슨 말을 할지 정하는 최소 예제입니다.

오목 미니게임을 만들면서 센 줄 수는 이랬습니다 — **수를 고르는 코드 522줄, 두면서 반응하는 코드 864줄.** 이기고 지는 것보다 그 상황에서 무슨 말을 하느냐에 더 많이 들어갔습니다.

이 폴더는 그중 발화 레이어만 떼어낸 것입니다.

> 블로그 글: (발행 후 링크)

## 돌려보기

```bash
node --experimental-strip-types --test barks.test.ts   # 결정론·발화율 검증
node --experimental-strip-types demo.ts                # 한 판 재생 + 발화율 측정
```

Node 22 이상이면 됩니다. 의존성도 빌드 단계도 없습니다.

## 무엇을 보여주는가

`demo.ts` 출력입니다.

```text
  [인사]   오늘은 내가 이길 것 같은데
  [ 1수] develop          이쯤에
  [ 2수] develop          (조용)
  [ 5수] open_three       (조용)
  [ 6수] crisis           막아야겠다
  [ 9수] win_five         다섯 개!
  [승리]   내가 이겼다!

두 번째 재생: 완전히 같다. 시드와 수순만으로 재현된다.
```

측정한 발화율입니다 (2,000수 표본).

| 발화 지점 | 등급 | 실측 |
| --- | --- | ---: |
| `win_five` · `crisis` | 항상 | 100.0% |
| `four` | 중간 | 51.7% |
| `open_three` | 중간 | 49.2% |
| `develop` | 낮음 | 19.0% |
| `think` | 낮음 | 19.6% |

## 판단이 갈리는 곳 세 군데

### 엔진이 좌표가 아니라 이유를 돌려준다

수를 두는 이유가 11가지(`Tactic`)입니다. 좌표만 있으면 캐릭터는 "뒀다"밖에 못 하지만, 이유가 있으면 **막을 때와 노릴 때 다른 말**을 할 수 있습니다.

대사 테이블이 이 11가지를 그대로 키로 씁니다. 엔진 쪽에 몇 줄 안 되는 변경이 반응 쪽에 289줄을 열어 줍니다.

### 생성 모델이 꺼져 있어도 완결된다

여기 있는 대사만으로 대국 시작부터 끝까지 돌아갑니다. LLM이 켜져 있을 때 하는 일은 **다음에 나갈 대사의 내용을 바꿔치기하는 것뿐**이고, 발화의 유무와 타이밍은 언제나 기본 레이어가 정합니다.

순서가 뒤집히면 어떻게 되는지는 쉽게 그려집니다. 응답이 늦으면 캐릭터가 뒀는데 3초 뒤에 말하고, 실패하면 그 수에만 조용합니다. **부가 기능이 빠졌을 때 기본 경험에 구멍이 나면, 그건 부가 기능이 아니라 의존입니다.**

### `Math.random()`을 쓰지 않는다

`(시드, 수순, 발화 키)`를 섞어 만든 값으로 난수 생성기를 만듭니다. 같은 판을 같은 순서로 다시 두면 캐릭터가 같은 말을 합니다.

"저기서 이상한 말을 했다"는 제보를 받았을 때 시드와 수순만으로 재현됩니다. **재현할 수 없는 대사는 고칠 수도 없습니다.**

## 원본과 다른 점

앱에서는 이 레이어 위에 연출(`character-director.ts` 349줄)이 얹힙니다 — 말풍선 표시 시간, 돌을 집고 놓는 애니메이션, 자세 전환. DOM과 타이머를 쓰는 코드는 그쪽 한 곳에 몰아 두고, 여기는 순수 함수로 남깁니다.

이 폴더에는 **대사를 고르는 부분만** 있습니다.
