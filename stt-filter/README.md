# stt-filter

로컬 음성 인식이 돌려준 전사 결과를 받아들이기 전에 거르는 최소 예제입니다.

Whisper를 마이크에 붙여 두면 **아무도 말하지 않은 구간에서 `[음악]` 같은 결과가 들어옵니다.** 학습 데이터에 자막이 많아서 생기는 일입니다. 그것만 골라 버리는 것이 이 코드의 목적입니다.

> 블로그 글: (발행 후 링크)

## 돌려보기

```bash
cargo test    # 판정 규칙 5가지 검증
cargo run     # 무엇이 통과하고 무엇이 걸리는지 표로 출력
```

의존성이 없습니다. Rust만 있으면 됩니다.

## 무엇을 하는가

`accept_transcript()` 하나가 입구입니다. 세 단계를 지납니다.

| 단계 | 거르는 것 | 결과 |
| --- | --- | --- |
| 1 | 빈 결과, 대괄호 자막 표기 | `Empty` |
| 2 | 4KB 초과 또는 1,000자 초과 | `TooLarge` |
| 3 | 제어문자, `<think`, 코드펜스 | `Unsafe` |

## 판단이 갈리는 곳 세 군데

### 숫자가 있으면 거르지 않는다

`[음악]`은 버리는데 `[00:12]`는 통과시킵니다. 자막 표기는 라벨이라 숫자가 없고, 숫자가 들어간 대괄호는 진짜 내용일 가능성이 있기 때문입니다.

**애매하면 통과시키는 쪽으로 기울여 놨습니다.** 진짜 발화를 버리면 사용자는 다시 말해야 하지만, 환청을 한 번 통과시키면 캐릭터가 헛소리를 한 번 할 뿐입니다.

### 상한이 두 개다

한글 한 글자는 UTF-8로 3바이트입니다. 바이트 상한만 두면 한글은 1,365자, 영문은 4,096자까지 들어와 언어에 따라 세 배 차이가 납니다. 글자 수 상한을 함께 두면 어느 언어든 1,000자에서 끊깁니다.

### 걸러낸 결과는 오류가 아니다

대괄호 표기는 **빈 결과와 똑같이** 취급합니다. "잘못된 입력입니다"가 아니라 "아무 말도 안 들렸다"입니다.

오류로 처리하면 캐릭터가 "잘 못 알아들었어요"라고 말합니다. 사용자는 말한 적이 없는데 그 소리를 듣습니다.

## 알려진 빈틈

`[]`는 통과합니다. 조건이 "안이 비어 있지 않을 것"이라 빈 대괄호가 빠집니다. 실제로 이런 결과를 본 적이 없어 지금은 막지 않습니다. 테스트에 그대로 적어 뒀습니다.

## 원본과 다른 점

앱에서는 HTTP 응답 파싱, 요청 취소, 토큰 관리가 함께 붙어 있습니다. 여기서는 **판정 규칙만** 남겼습니다. 규칙을 보는 데는 그것으로 충분합니다.
