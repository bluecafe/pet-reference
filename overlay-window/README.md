# overlay-window

화면 위에 항상 떠 있으면서 **빈 곳의 클릭은 뒤로 통과시키는 창**의 최소 예제입니다.

창은 사각형인데 캐릭터는 사각형이 아닙니다. 그대로 두면 캐릭터 옆 빈 공간을 눌렀는데 뒤에 있는 브라우저가 아니라 이 창이 반응합니다.

> 블로그 글: (발행 후 링크)

## 돌려보기

```bash
node --test hit-test.test.js   # 판정 로직만 검증 (의존성 없음)
cargo run                      # 실제 창을 띄운다 (Tauri 필요)
```

창이 뜨면 파란 원이 위아래로 움직입니다. 왼쪽 위 배지가 커서 아래에 무엇이 있는지 실시간으로 보여줍니다.

- **원 위** → `캐릭터가 받는다`
- **배지 위** → `UI가 받는다`
- **빈 곳** → `통과 (뒤 창이 받는다)` — 이 상태에서 뒤에 있는 창을 그대로 클릭할 수 있습니다

원을 끌면 창이 움직입니다.

## 앞의 셋과 다른 점

`stt-filter`·`prompt-budget`·`store-lock`은 의존성이 없지만 이 예제는 **Tauri가 필요합니다.** 창이 실제로 떠야 확인되는 내용이라 어쩔 수 없습니다.

대신 판정 로직은 `ui/hit-test.js` 하나로 떼어 놨습니다. DOM도 Tauri도 참조하지 않는 순수 함수라 `node --test`로 검증됩니다. 창을 띄우지 않고도 규칙이 맞는지 볼 수 있습니다.

## 설정으로 끝나는 부분

투명·테두리 없음·항상 위는 전부 `tauri.conf.json` 설정입니다. 코드가 아닙니다.

| 옵션 | 효과 |
| --- | --- |
| `transparent` | 배경을 비운다 |
| `decorations` | 제목 표시줄과 테두리를 없앤다 |
| `alwaysOnTop` | 다른 창 위에 머문다 |
| `skipTaskbar` | 작업표시줄·독에 항목을 만들지 않는다 |
| `shadow` | 창 그림자를 끈다 |
| `acceptFirstMouse` | 비활성 상태에서 첫 클릭이 바로 먹힌다 |

`shadow`를 빼먹기 쉬운데, 켜져 있으면 투명한 빈 공간에도 네모난 그림자가 남아 사각형 윤곽이 그대로 보입니다.

macOS에서는 `macOSPrivateApi`가 켜져 있어야 투명 창이 됩니다. **이 옵션을 쓴 앱은 App Store에 올릴 수 없습니다.**

## 판단이 갈리는 곳 네 군데

### UI를 알파값보다 먼저 본다

캔버스 위에 얹은 말풍선이나 버튼은 캔버스 픽셀이 아니라 알파값이 0으로 나옵니다. 알파값만 보면 **버튼이 보이는데 클릭이 뒤로 빠져나갑니다.**

그래서 `elementsFromPoint`로 그 자리에 마우스를 받는 요소가 있는지 먼저 확인합니다.

### `pointer-events: none`을 반드시 걸러낸다

장식용으로 얹어둔 레이어가 화면 전체를 덮고 있으면, 그것 때문에 **창 전체가 클릭을 먹습니다.** 예제의 점선 테두리(`#decoration`)가 그런 요소이고, 테스트가 이 경우를 확인합니다.

### 판정에 실패하면 통과시키지 않는다

`getImageData`는 캔버스 상태에 따라 실패합니다. 이때 통과로 처리하면 캐릭터를 눌렀는데 뒤에 있는 창이 반응합니다.

**모를 때는 받아 두는 쪽**이 낫습니다. 클릭이 안 먹는 것보다 엉뚱한 창이 반응하는 게 더 이상합니다.

### 좌표는 반드시 환산한다

창 크기와 캔버스 해상도가 다를 수 있습니다. 비율 환산을 빼먹으면 판정 위치가 캐릭터와 어긋나서, 고해상도 화면에서 캐릭터 오른쪽 아래를 눌러야 반응하는 증상이 생깁니다.

## 여기 없는 것

**Windows 네이티브 드래그 처리.** 네이티브 드래그가 시작되면 WebView가 `pointerup`을 못 받는 경우가 있습니다. 그러면 마우스를 놓았는데도 캐릭터가 커서에 붙어서 안 떨어집니다.

앱에서는 드래그를 시작한 뒤 브라우저 이벤트를 기다리는 대신 OS 쪽 마우스 버튼 상태를 주기적으로 확인하고, 그것마저 실패할 때를 대비한 시간 제한을 둡니다. 여기서는 뺐습니다 — 플랫폼별 네이티브 호출이 붙어 예제가 두 배가 됩니다.

클릭과 드래그를 가르는 기준(`isDrag`)은 판정 모듈에 남겨 뒀습니다.

**스프라이트 애니메이션.** 캐릭터 대신 도형을 그립니다. 알파값 판정은 무엇을 그리든 똑같이 동작하고, 캐릭터 에셋은 공개 대상이 아닙니다.
