# asset-pipeline

생성된 캐릭터 프레임을 시트에 넣기 전에 거르는 최소 예제입니다.

이미지 생성으로 프레임을 만들면 **배경이 투명하게 나오지 않습니다.** 단색을 깔고 나중에 빼야 하는데, 그 과정에서 프레임마다 결과가 달라집니다. 수백 장을 눈으로 확인할 수 없으니 숫자로 봅니다.

> 블로그 글: (발행 후 링크)

## 돌려보기

```bash
cargo test    # 판정 규칙 10개
cargo run     # 프레임 다섯 장을 검사해 무엇이 걸리는지 출력
```

의존성이 없습니다. PNG 디코딩은 범위 밖이라 픽셀 배열을 직접 받습니다.

## 무엇이 걸리는가

`cargo run` 출력입니다.

```text
  정상                 16384 →    3600 픽셀
  정상                 16384 →    3844 픽셀
  배경만                16384 →       0 픽셀
  셀을 꽉 채움            16384 →   16384 픽셀
  배경이 덜 빠짐           16384 →   12100 픽셀

  2번  비었다 — 배경만 있었거나 전부 지워졌다
  3번  여백에 닿는다 — 시트에서 옆 프레임과 붙어 보인다
  4번  픽셀 수가 튄다 (12100 vs 중앙값 3844)
```

## 판단이 갈리는 곳 네 군데

### 배경색은 캐릭터에 안 나오는 색으로

마젠타(`#FF00FF`)를 씁니다. 살구색이나 회색을 깔면 **피부와 옷이 같이 지워집니다.**

### 관용값은 양쪽으로 위험하다

생성 이미지는 배경이 미세하게 번집니다. 정확히 같은 색만 지우면 가장자리에 배경이 남습니다.

그렇다고 값을 키우면 캐릭터의 붉은 계열이 마젠타와 가까워서 같이 지워집니다. 테스트에 두 방향을 다 넣어 뒀습니다.

| 관용값 | 결과 |
| --- | --- |
| 0 | 번진 가장자리가 남는다 |
| 12 정도 | 배경만 지워진다 |
| 90 | 붉은 계열 캐릭터가 통째로 사라진다 |

### 프레임 하나만 보면 정상인지 알 수 없다

불투명 픽셀이 3만 개라는 게 많은 건지 적은 건지는 **다른 프레임과 비교해야** 압니다. 그래서 묶어서 보고 중앙값에서 벗어나는 것을 찾습니다.

실제 리포트에 기록된 걷기 네 장의 값입니다.

```text
24643  24587  24626  24682
```

이 정도로 붙어 있는 게 정상입니다. 하나만 4만이 나오면 배경이 덜 빠진 것입니다.

### 여백에 닿으면 시트에서 붙어 보인다

셀 가장자리 24px 안쪽에 불투명 픽셀이 있는지 봅니다. 캐릭터가 셀을 꽉 채우면 시트에 넣었을 때 옆 프레임과 이어져 보입니다.

## 지문

`content_digest()`는 프레임 내용의 해시입니다. 빌드 사이에 내용이 바뀌었는지 보는 용도입니다.

**실제 파이프라인은 SHA-256을 씁니다.** 여기서는 의존성을 안 넣으려고 FNV-1a를 썼습니다 — 충돌 저항이 필요한 곳에는 쓰면 안 됩니다.

크기도 해시에 넣습니다. 픽셀 수가 같아도 4×2와 2×4는 다른 프레임입니다.

## 원본과 다른 점

실제 파이프라인은 PNG를 읽고 쓰고, 연결 요소로 프레임을 잘라내고, 아틀라스로 합칩니다. 여기서는 **판정 부분만** 남겼습니다.

리포트 형식도 원본에는 상태 이름과 프레임 번호가 함께 들어가지만, 여기서는 인덱스만 씁니다.
